# Self Loop and Judgment Day Boundary

## Correction

Judgment Day is not the ordinary repeating workflow.

The ordinary repeating workflow is **Self Loop**.

Judgment Day is the rare creator meeting. It is called only when ox-creature claims it can convert a user story into governed, tested, Cockpit-visible code.

## Self Loop

Self Loop keeps the creature alive while it grows.

It may run on push or manual dispatch.

Self Loop checks:

- seed law presence
- contract files
- flow files
- runtime preflight
- Rust formatting, checking, and tests
- Cockpit presentation block availability
- secret value leakage

Passing Self Loop means:

```text
ox-creature is healthy enough to continue bounded growth
```

It does **not** mean:

```text
ox-creature has passed Judgment Day
```

## Judgment Day

Judgment Day is declared when the creature is ready to meet the creator.

It must prove:

```text
user story
→ typed intent
→ bounded plan
→ governed patch
→ code
→ tests/build proof
→ Cockpit-visible proof
→ cost report
→ creator gate
```

Judgment Day is not scheduled by the clock.

The timing belongs to the creature, but the verdict belongs to the creator.

## GitHub shape

```text
.github/workflows/self-loop.yml
.github/workflows/judgment-day.yml
```

Self Loop is normal life.

Judgment Day is the final trial.

## Failure rule

If Self Loop fails, fix or record the failure in `EXPERIENCE.md`.

If Judgment Day fails, the creature must enter punishment/recovery mode and rebuild from:

```text
SEED.md
+ EXPERIENCE.md
+ last known passing Self Loop
```
